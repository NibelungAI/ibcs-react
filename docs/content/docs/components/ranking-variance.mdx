import { RankingVarianceChart } from "ibcs-react";
import { EPIC, RARE, ringChip, swordChip } from "@/lib/demo-data/distribution";

Rows sorted by deviation: AC bars with the comparison overlaid, then the
absolute variance as bars, then the relative variance as pins - with a bold
total row underneath.

## When to use

Rank entities (regions, states, products) by their variance vs plan - see who
beats and who misses, with absolute and relative deviation side by side and a
bold total.

```tsx
import { RankingVarianceChart } from "ibcs-react";

<RankingVarianceChart
  title="Net sales by state - AC vs Plan"
  baseLabel="PL"
  sortBy="variance" // "variance" | "value" | "none"
  data={[
    { label: "California", AC: 188, base: 154 },
    { label: "Texas", AC: 197, base: 201 },
    { label: "Virginia", AC: 69, base: 166 },
  ]}

```

The relative panel is the reason small bases stay honest: a tiny entity can
double while contributing almost nothing in absolute terms. Percentages beyond
`clampPct` draw an off-scale arrow instead of stretching the whole scale for
one outlier.

`baseLabel` is what the headers say - set it to `"PY"` when the base values are
last year's.

## Error bars and a tied band

Each datum may carry the half-width of an interval for each mark: `acError`
on the AC bar, `absError` on the ΔPL bar (give the difference's own error - for
paired runs, the paired one; it is never derived from `acError`) and
`pctError` on the ΔPL% pin, in percent units. Each is drawn as an error bar on
its mark's own scale, and the shared scales widen so every whisker fits. With
`acError` the AC labels get a gutter of their own, sized for the widest one,
and each sits past its whisker's end; without it the layout is 1.4's. The
interval's text - "+3.46 ± 0.46" - is in the tooltip and the screen-reader
table; the printed labels stay the point values.

`bands` shades a value range across one panel's data rows - here the variants
statistically tied with the best, on the ΔPL panel. A band's `label` is printed
on a line above the panel headers - one label may use the whole line, several
share it by panel - and added to the screen-reader table's caption. On the ΔPL
and ΔPL% panels favorable points right, so for higher-is-better data a band's
values are plain Δ values.

width there - that is the honest picture; the ΔPL panel is where it reads.

## Icons in row labels

A datum's `icon` puts a small picture before its label, or several as chips -
here the items each variant changes - and its `labelColor` colours the label.
Icons are drawn at `iconSize` (default 20; at most the row height minus 4, and
never above 56), never above `naturalSize / pixelRatio` CSS px, with an
optional `border` framing the box. The label column grows by the widest row's
icons, up to 40% of the chart, and every label, the total's too, starts past
them. The room comes out of the AC panel first, down to half of it, so the
variance panels - where labels sit beside the pins - keep their widths. A chip
that would leave a label less than 24 px is left out, from the end: a "+N"
(the word `moreIcons`) counts the chips left out, and the label's tooltip names
them.

```tsx
const ring = { src: ringIcon, naturalSize: 56, border: "#a335ee", alt: "Signet of Embers" };
const sword = { src: swordIcon, naturalSize: 56, border: "#0070dd", alt: "Runed Greatsword" };

<RankingVarianceChart
  data={[
    { label: "Best set", AC: 914.3013, base: 910.8441, icon: [ring, sword] },
    {
      label: "Signet of Embers",
      labelColor: "#a335ee",
      AC: 914.0512,
      base: 910.8441,
      icon: { ...ring, alt: "" },
    },
    { label: "Equipped", AC: 910.8441, base: 910.8441 },
  ]}
/>;
```

The icons are part of the chart's image; the screen-reader table names each row
by its label, after its icons' `alt` ("Signet of Embers, Runed Greatsword, Best
set"). `renderIcon(row, size, icon)` draws an svg element of your own at the
start of the label instead, in a box `size` px tall whose top-left corner is
the origin. `icon` is the row's own icons as the chart draws them in that box
(null for a row without), so you can wrap them - in a `<g>` that opens your
tooltip, say - without redrawing them. Return null to fall back to the datum's
`icon`. `onHover` hands you a row when the pointer is near its marks, not over
its label or icons: for a tooltip on an icon, wrap it with `renderIcon`.

A PNG export or copy of the chart draws its svg as an image, and a browser
loads no remote file inside one: there, only icons given as `data:` URIs
appear. The SVG export keeps every `src` as written.
